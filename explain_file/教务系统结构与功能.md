## 一、项目概览

一个面向学校的教务管理系统，支持三种角色：**学生**、**教师**、**教务管理员**。

| 项目属性 | 值 | 依据 |
|---|---|---|
| 后端框架 | Flask 3.1.3（Python 3.11+） | `requirements.txt`（版本已锁定） |
| 数据库 | MySQL（PyMySQL 驱动 + DBUtils 连接池） | `config.py` / `core.py` |
| 数据表数量 | 28 张 | `schema.sql` 中 `CREATE TABLE` 计数 |
| 前端 | 原生 HTML + JavaScript（无前端框架），后端 JSON API + 浏览器渲染 | `templates/`（52 个 HTML）+ `static/js/` |
| 后端代码规模 | 8 个核心 `.py` 文件共 4076 行 | `wc -l` 实测 |
| 测试 | pytest 78 个用例 | 实测全通过 |

### 核心模块结构（代码审阅）

| 文件 | 职责 |
|---|---|
| `app.py` | 应用入口、蓝图注册、安全中间件（CSRF、安全响应头、HTTPS 跳转）、错误处理 |
| `core.py` | 数据库连接池、登录装饰器（`login_required`/`role_required`）、登录限流、密码策略、敏感字段加密、Excel 导出 |
| `auth.py` | 登录/登出、登录验证码、修改密码、头像上传 |
| `common.py` | 公告等公共数据接口 |
| `student.py` | 学生端：选课、课表、成绩、评教、各类申请 |
| `teacher.py` | 教师端：授课、成绩录入、评教查看 |
| `admin.py` | 管理端：学生/教师/课程/成绩/审核/日志（体量最大，约 84KB） |
| `config.py` | 配置加载（MySQL、会话密钥、学期） |

数据库表（28 张，`schema.sql` 实测列出）：`admin`、`college`、`major`、`class`、`student`、`teacher`、`course`、`course_offering`、`classroom`、`section_time`、`course_schedule`、`offering_class`、`enrollment`、`exam`、`evaluation`、`retake_apply`、`status_change_apply`、`project`、`project_apply`、`credit_substitute_apply`、`innovation_credit`、`registration`、`certificate`、`teaching_plan`、`announcement`、`operation_log`、`login_captcha`、`login_throttle`。

## 三、安全技术

> 说明：本节的「实测」均基于 Flask 测试客户端或本机真实 TCP 请求，对独立测试库 `edu_admin_test` 操作，未触碰演示数据。

### 3.1 认证与会话

| 机制 | 实现方式 | 验证状态 |
|---|---|---|
| 密码存储 | bcrypt 哈希（生产默认 cost=12），**明文不落库** | 代码审阅 |
| 密码策略 | 长度 8~72 位、必须含字母+数字、常见弱口令黑名单拦截 | 实测（弱口令/短口令均被拒） |
| 登录验证码 | 4 位图形验证码（剔除易混字符 0/O/1/I/L），答案存 MySQL 而非进程内存 | 代码审阅 |
| 验证码一次性 | 原子消费（比对+删除在一条 SQL），无论对错都失效，5 分钟过期 | 实测（同 token 重放被拒） |
| 登录限流 | 双通道、**数据库存储**（跨 worker 共享、重启不丢）：IP 连续失败 5 次锁 10 分钟、账号连续失败 10 次锁 15 分钟（防分布式换 IP） | 实测（IP/账号均触发 429，20 线程并发无丢失更新） |
| 会话 Cookie | **服务端会话（Flask-Session）**：数据存服务器，Cookie 只留随机 session_id；HttpOnly + SameSite=Lax + 签名，7 天有效期 | 实测（Cookie 解码无明文身份数据、登录/登出/CSRF 均正常） |
| 会话固定防护 | 登录成功后 `session.clear()` 重建身份 | 代码审阅 |
| 多端踢下线 | 会话保存密码指纹，改密后其他设备旧会话写操作即失效 | 代码审阅 |
| 初始密码 / 强制改密 | 新建/重置/导入账号初始密码默认 `123456`（`DEFAULT_INITIAL_PASSWORD` 可覆盖），不强制首次改密；`must_change_pwd` 机制保留，置 1 时改密前只放行改密接口 | 实测（2024006/临时学生均可用 123456 直接登录） |
| 防用户名枚举 | 登录失败统一返回「用户名或密码错误」 | 实测（两类错误文案一致） |

### 3.2 注入与跨站防护

| 机制 | 实现方式 | 验证状态 |
|---|---|---|
| SQL 注入防护 | 全站参数化查询（`%s` 占位）；表名/列名仅来自固定白名单字典 | 实测（登录/搜索 7 种 payload 全部失败） |
| CSRF 防护 | 双提交令牌：写操作必须携带与 Cookie 一致的 `X-CSRF-Token` 头 | 实测（缺失/伪造令牌均 403） |
| XSS 防护 | 前端统一 `esc()`/`escJs()`/`jsAttr()` 转义；内联事件已全部改为 `data-*` 委托；CSP `script-src 'self'`（无 unsafe-inline）三重封堵 | 实测（恶意 payload 被中和、零内联残留、CSP 头确认） |
| 路径穿越防护 | 静态资源经 `send_from_directory`，拒绝越界路径 | 实测（3 种 `../` 变体均 404，无源码泄露） |
| 输入净化（纵深防御） | 姓名/工号后端拒绝 `< >` 与控制字符（`validate_name`），从源头阻断存储型 XSS | 实测（恶意姓名被拒、正常姓名放行） |
| Excel 公式注入 | `safe_cell()` 对 `= + - @` 开头文本前置单引号 | 代码审阅 |

### 3.3 安全响应头与数据保护

| 机制 | 实现方式 | 验证状态 |
|---|---|---|
| 安全响应头 | CSP（`script-src 'self'` 无 unsafe-inline）、`X-Frame-Options: DENY`（防点击劫持）、`X-Content-Type-Options: nosniff`、`Referrer-Policy`、`Permissions-Policy`、HTTPS 下 HSTS | 实测（响应头齐全，`script-src 'self'` 确认） |
| 敏感数据加密 | 身份证号 AES-256-GCM 加密存储（密钥由 SECRET_KEY 经 HKDF 派生） | 代码审阅 |
| 敏感数据脱敏 | 身份证读取时脱敏（保留前 3 后 4 位） | 代码审阅 |
| 头像上传校验 | 扩展名白名单 + 文件头 magic bytes 校验 + 5MB 限制 + 服务端生成文件名 | 代码审阅 |
| 会话密钥管理 | 环境变量/本地密钥文件，拒绝占位符与弱密钥（<16 位自动忽略并生成随机密钥） | 代码审阅 |
| 数据库弱口令守卫 | 连接远程数据库却仍用默认/空口令时拒绝启动（本机开发仅警告） | 实测（远程+弱口令被拒启动） |

### 3.4 越权与审计

| 机制 | 实现方式 | 验证状态 |
|---|---|---|
| 角色鉴权 | `role_required` 装饰器：未登录 401、角色不符 403 | 实测（学生调管理接口均 403） |
| 管理员细分权限 | `perm_required('super')`：审计日志查看/清空/删除仅超级管理员可操作 | 实测（超管 200、普通管理员 403，普通管理员仍可用常规功能） |
| 数据隔离（防 IDOR） | 学生端所有查询锚定 `session['user_id']`，只能读写本人数据 | 实测（成绩仅返回本人） |
| 写操作状态复查 | 每次写操作前复查账号冻结/停用状态，被停用立即失效 | 代码审阅 |
| 操作审计 | `operation_log` 记录登录成败、增删改、IP；登录失败原因留存但对外模糊 | 代码审阅 |

### 3.5 本次安全测试结论

- **基线**：项目自带 pytest **78 个用例全部通过**（含安全测试），另有 **Node 前端安全回归测试 6 项**（`npm test`，覆盖 XSS 转义函数正确性、三份拷贝一致性、CSP 无内联残留、委托函数引用完整性）。
- **渗透检查**：共约 **37 项**（含复验）——覆盖 SQL 注入、CSRF、越权、路径穿越、暴力破解、验证码重放、会话 Cookie、密码策略、安全响应头、匿名访问控制，**全部通过**。
- **发现并已修复的问题**（2026-10-30）：
  1. **高危：存储型 XSS**（学生可通过个人资料 email 字段注入脚本至管理端）——已从前后端双重修复（前端 `jsAttr()` + 后端 email 字符白名单）。
  2. **低危：用户名枚举**——已统一登录错误文案。
  3. **低危：email 校验过宽**——已收紧正则。
  4. **加固：登录限流仅按 IP**——已新增账号级限流（防分布式换 IP 攻击）。
  5. **加固：姓名/工号零校验入库**——已新增 `validate_name` 输入净化（拒绝 `< >` 与控制字符）。
  6. **加固：数据库默认口令 `1234` 裸奔风险**——已新增启动守卫（远程库 + 弱口令拒绝启动）。

### 3.6 前端转义完整性审计结论

对全部 52 个 HTML 模板 + 3 个公共 JS 文件做了全量扫描（含多行模板字符串），结论：**所有落进 `innerHTML` 的字符串数据均被 `esc()`/`escJs()`/`jsAttr()` 转义**，无一处未转义的数据 sink；全站无 `eval`/`new Function`/`document.write`/`javascript:` URL。配合后端的 `validate_name` 输入净化，前端 XSS 攻击面已双层封堵。

### 3.7 前端架构重构（CSP 收紧，2026-10-30）为将 CSP 的 `script-src` 从 `'self' 'unsafe-inline'` 收紧为 `'self'`，对前端做了架构级改造：

- **52 个内联 `<script>` 块**全部外置为 `static/js/pages/<角色>/<页面>.js`，页面改为 `<script src>` 引用；
- **165 个内联事件处理器**（`onclick`/`ondblclick`/`onchange`/`oninput`）全部改为 `data-action`/`data-dbl`/`data-change`/`data-input` 属性，由公共 JS 里的统一事件委托分发（`data-arg` 携带 JSON 参数）；
- 4 个依赖 `this` 或函数回调的函数做了适配（`viewAvatar`/`toggleClass`/`switchTab`/`openImportDialog`）。

验证：55 个 JS 文件 `node --check` 语法全过；所有 `data-*` 引用的函数均存在；零内联脚本、零内联事件属性残留；页面经 HTTP 返回时正确引用外部 JS 且文件可达（200）；CSP 响应头确认 `script-src 'self'`。`style-src` 仍保留 `unsafe-inline`（内联样式分布极广，CSS 注入风险远低于脚本，属可接受残留）。

## 四、并发能力

### 4.1 选课超卖防护（核心并发考点）

选课名额抢占采用**数据库原子更新**实现（`student.py` 第 511 行）：

```sql
UPDATE course_offering SET selected_count = selected_count + 1
WHERE id=%s AND status='开放' AND selected_count < max_count
```

判断与修改在同一条 SQL 内原子完成，由 **InnoDB 行锁**保证，与 Python 进程数无关。同一学生重复选课由 `enrollment` 表 `UNIQUE KEY uk_student_offering (student_id, offering_id)` + 事务回滚兜底。

**实测结果（两项均通过，零超卖）**：

| 测试 | 场景 | 结果 |
|---|---|---|
| 单进程 | 60 线程同时抢 10 名额 | 成功恰好 10，50 人收到「人数已满」，计数器与真实行数一致，无 5xx |
| 多进程 | 4 个独立服务进程（真实 TCP），60 线程跨进程抢 10 名额 | 成功恰好 10，计数器一致，无重复占坑，无 5xx，请求均匀分布到 4 进程 |

### 4.2 吞吐量基线

> ⚠️ 以下为本机开发环境、Flask 测试客户端（单进程）实测，用于**相对量级参考**，不代表生产多 worker + 真实网络下的最终吞吐。

| 接口 | 实测耗时 | 折算吞吐 |
|---|---|---|
| 静态页面 `/` | 0.75 ms/次 | 约 1340 req/s |
| 健康检查 `/health`（含数据库） | 0.79 ms/次 | 约 1269 req/s |
| 公告接口 | 1.23 ms/次 | 约 812 req/s |
| 验证码（图片生成 + DB 写入） | 8.38 ms/次 | 约 119 req/s |
| bcrypt 密码校验（cost=12） | 230 ms/次 | 约 4 req/s |

**关键结论**：框架本身开销不足 1ms，性能瓶颈在数据库、图片生成与密码哈希。bcrypt 的 230ms 是**刻意的安全代价**（让暴力破解变慢），且已被验证码 + IP 限流前置拦截。

### 4.3 生产扩展设计

- 连接池：`PooledDB` 最大 20 连接，连接耗尽时阻塞等待而非报错；
- 进程模型：gunicorn `CPU×2+1` 个 sync worker、每 worker 2 线程（`gunicorn.conf.py`）；
- 超卖防护依赖 MySQL 行锁，因此**可安全地横向扩容 worker 数量**。
