## 一、项目概述

### 1.1 背景与目标

面向学校教务管理场景，构建一套覆盖**学生、教师、教务管理员**三类角色的综合教务系统，统一承载选课、成绩、课表、考试、评教、各类申请审核、公告通知、数据管理等核心业务，替代线下人工流转，提升教务运作效率与数据准确性。

### 1.2 系统范围

系统覆盖从「学籍与选课」到「成绩与证书」的完整教务闭环，具体包括：用户认证、信息维护、选课排课、成绩管理、考试安排、教学评价、申请审核、公告通知、数据导入导出、操作审计等模块。

### 1.3 技术栈（开发约束）

| 层 | 技术 |
|---|---|
| 后端 | Python 3.11+ / Flask 3.1（蓝图组织）、PyMySQL + DBUtils 连接池 |
| 数据库 | MySQL（utf8mb4，28 张表） |
| 前端 | 原生 HTML + JavaScript，JSON API + 浏览器渲染（无前端框架） |
| 部署 | gunicorn（多 worker）+ Nginx 反向代理 |
| 认证 | 服务端会话（Flask-Session）+ bcrypt 密码哈希 |

## 二、用户角色与权限

| 角色 | 标识 | 权限范围 |
|---|---|---|
| 学生 | `student` | 个人信息、选课、课表、成绩、考试、评教、各类申请、学分确认、注册、专业分流 |
| 教师 | `teacher` | 个人信息、授课管理、成绩录入、课表、评教查看、工作台 |
| 教务管理员 | `admin` | 全局管理：组织/人员/课程/排课/成绩/审核/公告/日志/导入导出 |
| 超级管理员 | `admin` + `is_super=1` | 在管理员基础上，额外拥有审计日志的查看与清除权限 |

**权限隔离原则**：
- 纵向隔离：角色不符返回 403，未登录返回 401；
- 横向隔离：学生、教师端所有数据查询均锚定当前登录用户 ID，禁止越权访问他人数据；
- 细分权限：管理员通过 `is_super` 标记区分「超级管理员 / 普通教务员」。

## 四、非功能需求

### 4.1 安全需求（强制）

| 编号 | 需求描述 |
|---|---|
| NFR-SEC-01 | 全站参数化 SQL，禁止字符串拼接（表名/列名仅允许白名单） |
| NFR-SEC-02 | 密码 bcrypt 哈希存储，明文不落库；强制密码强度策略 |
| NFR-SEC-03 | 登录必须通过图形验证码（一次性、5 分钟过期） |
| NFR-SEC-04 | 登录限流：IP 连续失败 5 次锁 10 分钟、账号连续失败 10 次锁 15 分钟（数据库存储，跨进程共享） |
| NFR-SEC-05 | 写操作必须携带 CSRF 令牌（双提交 Cookie） |
| NFR-SEC-06 | 前端所有动态内容必须经转义函数（esc/escJs/jsAttr）输出 |
| NFR-SEC-07 | 敏感字段（身份证号）AES-256-GCM 加密存储 + 展示脱敏 |
| NFR-SEC-08 | CSP `script-src 'self'`（无 unsafe-inline），全站禁用内联脚本与内联事件 |
| NFR-SEC-09 | 会话采用服务端存储，Cookie 只留 session_id（HttpOnly + SameSite + 签名） |
| NFR-SEC-10 | 数据库远程连接禁用弱口令（弱口令拒绝启动） |

### 4.2 性能需求

| 编号 | 需求描述 |
|---|---|
| NFR-PERF-01 | 常规查询接口在单机环境下吞吐 ≥ 500 req/s（实测公告接口约 812 req/s） |
| NFR-PERF-02 | 连接池复用数据库连接（最大 20 连接，连接耗尽阻塞等待） |
| NFR-PERF-03 | 登录 bcrypt 校验为刻意慢哈希（约 230ms），由验证码+限流前置缓解 |

### 4.3 并发正确性需求（强制）

| 编号 | 需求描述 |
|---|---|
| NFR-CONC-01 | 选课名额抢占必须原子化，任何并发下不得超卖（实测 60 线程/多进程抢 10 名额零超卖） |
| NFR-CONC-02 | 同一学生同一课程不得重复占坑（唯一约束 + 事务回滚兜底） |

## 六、接口约定

- **协议**：HTTP/HTTPS，同源部署；
- **数据格式**：请求/响应均为 `application/json`；统一响应结构 `{ "success": bool, "message": str, "data": ... }`；
- **认证**：服务端会话 Cookie（`session`），前端登录后由后端维持；
- **CSRF**：写操作（POST/PUT/DELETE）须携带请求头 `X-CSRF-Token`（值取自 `csrf_token` Cookie）；
- **错误码**：401 未登录、403 无权限/CSRF 失败、404 资源不存在、429 限流、500 服务器错误。

## 八、验收标准（摘要）

1. 三类角色登录、退出、改密、头像全流程可用；
2. 学生选课/退选、成绩查询、评教、四类申请、注册、分流可用，且并发选课不超卖；
3. 教师成绩录入（手动/导入）、比例设置、课表、评教查看可用，且不能访问他人教学班；
4. 管理员完成组织/人员/课程/排课/审核/公告/导入全流程，普通管理员不能查看审计日志；
5. 全部安全需求（4.1 节）通过安全回归测试；
6. 后端 78 项 + 前端 6 项测试全绿。
