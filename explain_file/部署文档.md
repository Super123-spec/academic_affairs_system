# 部署文档

> 本文由原《DEPLOY.md》（部署指南）与《部署命令速查.md》（命令速查）合并而成，涵盖从上传、初始化到生产运行、开机自启的完整流程。
> 环境：OpenEuler + Python 3.9+（推荐 3.11）+ MySQL 8，项目路径 `/opt/教务管理系统`；Windows 用于本地开发。
> 安全提示：所有 IP、密钥均为占位符，请替换为自己的值，**不要把真实密码/密钥写进文档提交**。

## 一、需要传输的文件

整个项目目录，排除以下无用项即可：

```
app.py  config.py  wsgi.py  gunicorn.conf.py  schema.sql  init_db.py  upgrade_db.py
requirements.txt  requirements-prod.txt  .env.example
start.sh
static/  templates/
```

可排除：`__pycache__/`、`.workbuddy/`、`logs/`、`.secret_key`（会在目标机自动生成）、`.db_initialized`、`.venv/`、测试脚本与文档。

## 二、Linux 服务器首次部署完整流程

### 1. 上传项目

在本地执行（替换 `<服务器IP>`）：

```bash
scp -r "教务管理系统" <用户名>@<服务器IP>:/opt/
```

> 分发包里已移除 `.secret_key`（首次启动会自动生成），`.env` 也需要在服务器上新建。

### 2. 装编译依赖（只需一次）

```bash
dnf install -y python3-devel gcc gcc-c++
```

### 3. 创建虚拟环境

```bash
cd /opt/教务管理系统
python3 -m venv venv
source venv/bin/activate
```

### 4. ⚠️ 升级 pip（关键，必须做）

```bash
python -m pip install --upgrade pip -i https://mirrors.aliyun.com/pypi/simple/
```

> **为什么必须升级**：老版本 pip 不认识 `manylinux_2_28` 格式的预编译包，会退回源码编译 bcrypt，而编译需要 Rust 编译器 → 报 `error: can't find Rust compiler`。

### 5. 安装依赖

```bash
pip install -r requirements.txt -r requirements-prod.txt -i https://mirrors.aliyun.com/pypi/simple/
```

依赖版本已在 `requirements.txt` 中锁定（Flask 3.1.3 一组），安装结果是确定的。

> 若服务器只能是 Python 3.7，请勿直接使用本版本依赖（Flask 3.1 不支持 3.7），建议升级到 3.9+。

### 6. 配置数据库连接

```bash
cp .env.example .env
vi .env
```

至少修改以下几行（`SECRET_KEY` 用命令生成，不要手写弱口令）：

```bash
python -c "import secrets;print(secrets.token_hex(32))"   # 生成 SECRET_KEY
```

```ini
MYSQL_PASSWORD=<你的MySQL强密码>
SECRET_KEY=<上一步生成的长随机字符串>
TRUST_PROXY=0        # 直连部署填 0；Nginx 反代填 1
```

验证：

```bash
grep -E "MYSQL_PASSWORD|SECRET_KEY|TRUST_PROXY" .env
```

### 7. 初始化数据库（仅首次）

```bash
python init_db.py --yes
```

> ⚠️ 此脚本会 **TRUNCATE 清空所有表**。脚本已加二次确认：不加 `--yes` 会先询问；非交互环境不加 `--yes` 会直接退出，避免误跑。已有数据时切勿重跑，请用第 8 节的 `upgrade_db.py`。

### 8. 启动服务

**生产环境：gunicorn（唯一推荐方式）**

```bash
pkill -f "gunicorn.*wsgi:app" || true       # 先停旧服务，避免端口占用
chmod +x start.sh
ls logs || mkdir -p logs                    # 日志目录（已配置轮转）
source venv/bin/activate
gunicorn -c gunicorn.conf.py wsgi:app --daemon
sleep 2 && tail -n 30 logs/error.log
```

**本地开发：Flask 开发服务器（切勿用于生产）**

```bash
FLASK_DEBUG=1 python app.py
```

> Flask 自带开发服务器单进程、无并发保护、无超时控制，生产必须用 gunicorn。

### 9. 放行防火墙

```bash
firewall-cmd --permanent --add-port=5000/tcp
firewall-cmd --reload
firewall-cmd --list-ports      # 确认有 5000/tcp
```

### 10. 访问

浏览器打开 `http://<服务器IP>:5000`（配置 HTTPS 见第五节）。

## 四、关键安全配置（生产必做）

| 配置项 | 说明 |
|---|---|
| `SECRET_KEY` | 必须改为随机长字符串（通过 .env 注入，勿硬编码） |
| `MYSQL_PASSWORD` | 必须用强密码，且 MySQL 账号只授权本库（远程连接用弱口令会被拒绝启动） |
| `SESSION_COOKIE_SECURE=1` | 若用 HTTPS 访问，务必开启 |
| `FLASK_DEBUG` | 生产环境保持 0 或删除 |
| `ALLOWED_ORIGINS` | 前后端分离跨域时才配置，同源部署留空 |
| `TRUST_PROXY` | 反代部署设 1，直连设 0（详见第六节） |

## 五、反向代理 + HTTPS（Nginx）

```nginx
server {
    listen 80;
    server_name your-domain.com;
    return 301 https://$host$request_uri;   # 强制跳 HTTPS
}

server {
    listen 443 ssl;
    server_name your-domain.com;
    ssl_certificate     /path/to/fullchain.pem;
    ssl_certificate_key /path/to/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:5000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

> ⚠️ **使用反向代理时必须在 `.env` 里设置 `TRUST_PROXY=1`**（并保持 `FORWARDED_ALLOW_IPS=127.0.0.1`）。
> 否则 gunicorn 看到的来源 IP 全是 `127.0.0.1`，登录限流会把所有用户当成同一个人，5 次失败后全校都无法登录。
> 直连部署（不经过代理）则保持 `TRUST_PROXY=0`，因为此时任何 `X-Forwarded-For` 都由客户端伪造。

## 六、日常启动 / 停止 / 查看

```bash
cd /opt/教务管理系统
source venv/bin/activate

# 启动
gunicorn -c gunicorn.conf.py wsgi:app --daemon

# 查看是否在跑
ps aux | grep "gunicorn.*wsgi:app" | grep -v grep
ss -tlnp | grep 5000

# 实时看日志（自动轮转，单文件上限 10MB，保留 5 份）
tail -f logs/error.log
tail -f logs/access.log

# 平滑重启（不中断连接）
kill -HUP $(cat /opt/教务管理系统/gunicorn.pid 2>/dev/null || pgrep -f "gunicorn.*wsgi:app" | head -1)

# 停止
pkill -f "gunicorn.*wsgi:app"
```

## 七、代码更新后升级（不要重跑 init_db）

**绝对不要重跑 `init_db.py`**（会清空数据）。用：

```bash
cd /opt/教务管理系统
source venv/bin/activate
python upgrade_db.py
```

`upgrade_db.py` 是**幂等**的，可重复执行，只补缺失的表和数据（按 `schema.sql` 自动补齐缺失表），不动已有业务数据。看到 `[+]` 表示新增、`[=]` 表示已存在跳过。执行完重启服务生效：

```bash
pkill -f "gunicorn.*wsgi:app"
gunicorn -c gunicorn.conf.py wsgi:app --daemon
```

## 八、实际踩过的坑（备查）

| 报错 | 原因 | 解决 |
|---|---|---|
| `No matching distribution found for Flask==3.1.3` | 系统 Python 版本过低（<3.9） | 升级 Python 到 3.9+ |
| `error: can't find Rust compiler` | pip 太旧，退回源码编译 bcrypt | **升级 pip** |
| `ModuleNotFoundError: No module named 'bcrypt'` | 上一条导致没装上 | 同上 |
| `Address already in use` / `Port 5000 is in use` | 旧服务还占着端口 | `pkill -f "gunicorn.*wsgi:app"` 后重启 |
| 所有用户同时提示"登录失败次数过多" | 反代部署却未设 `TRUST_PROXY=1`，全部用户共用代理 IP | `.env` 设 `TRUST_PROXY=1` 后重启 |
| `bash: cd /教务管理系统: 没有那个文件或目录` | 路径少了 `/opt` | `cd /opt/教务管理系统` |
| `venv/bin/pip: 没有那个文件或目录` | 删了 venv 但 shell 还激活着 | 先 `deactivate` 再重建 |
| `pip: command not found`（升级后） | 命令粘贴重复导致参数错乱 | 一次只粘一条命令 |

## 十、开机自启（systemd，可选）

创建系统用户（**不要用 root 运行 Web 服务**）：

```bash
useradd --system --create-home --home-dir /opt/eduapp --shell /sbin/nologin eduapp
chown -R eduapp:eduapp /opt/教务管理系统
```

创建 `/etc/systemd/system/edu.service`：

```ini
[Unit]
Description=教务管理系统
After=network.target mysqld.service

[Service]
Type=simple
User=eduapp
Group=eduapp
WorkingDirectory=/opt/教务管理系统
EnvironmentFile=/opt/教务管理系统/.env
ExecStart=/opt/教务管理系统/venv/bin/gunicorn -c gunicorn.conf.py wsgi:app
Restart=always
RestartSec=5

# 基础加固：限制可写范围与提权
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=full
ProtectHome=true
ReadWritePaths=/opt/教务管理系统/logs /opt/教务管理系统/static/uploads

[Install]
WantedBy=multi-user.target
```

启用：

```bash
pkill -f "gunicorn.*wsgi:app"      # 先停掉手动启动的
systemctl daemon-reload
systemctl enable edu
systemctl start edu
systemctl status edu
```

> 注意：`static/uploads/avatar/` 需对 `eduapp` 用户可写，否则头像上传会失败。
